API Reference Documentation

This document provides a comprehensive reference for our REST API. All endpoints require authentication using API keys.

Authentication

All API requests must include an API key in the header:

Authorization: Bearer YOUR_API_KEY

You can generate API keys from your account settings page. Keys should be kept secure and never shared publicly.

Base URL

All API endpoints are relative to: https://api.example.com/v1

Endpoints

Users Endpoint
GET /users
Retrieves a list of all users in your organization.

Parameters:
- page (optional): Page number for pagination (default: 1)
- limit (optional): Number of results per page (default: 20)

Response:
{
  "users": [...],
  "total": 150,
  "page": 1
}

GET /users/{id}
Retrieves details for a specific user by ID.

Parameters:
- id (required): User ID

Response:
{
  "id": "12345",
  "name": "John Doe",
  "email": "john@example.com",
  "created_at": "2024-01-15T10:30:00Z"
}

POST /users
Creates a new user account.

Request Body:
{
  "name": "Jane Smith",
  "email": "jane@example.com",
  "role": "member"
}

Response: Returns the created user object with status 201.

Projects Endpoint
GET /projects
Retrieves all projects accessible to the authenticated user.

POST /projects
Creates a new project.

Request Body:
{
  "name": "New Project",
  "description": "Project description"
}

Rate Limiting

API requests are limited to 1000 requests per hour per API key. Rate limit information is included in response headers:

X-RateLimit-Limit: 1000
X-RateLimit-Remaining: 999
X-RateLimit-Reset: 1640000000

Error Codes

- 400 Bad Request: Invalid request parameters
- 401 Unauthorized: Invalid or missing API key
- 404 Not Found: Resource not found
- 429 Too Many Requests: Rate limit exceeded
- 500 Internal Server Error: Server error

All errors return a JSON response with details:
{
  "error": "Error message",
  "code": "ERROR_CODE"
}
